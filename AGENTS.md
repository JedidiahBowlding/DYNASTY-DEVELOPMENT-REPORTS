# Public reporting rules

Keep this checkout limited to documentation and sanitized visual previews embedded in milestone reports. Use the milestone template, distinguish verified results from assumptions, and tie aggregate evidence to the tested source revision. Publish only approved summaries. Exclude source and diffs, proprietary details, credentials, private paths, internal infrastructure, customer information, model weights and unreleased assets. Validate the entire outgoing snapshot and show the complete diff. Block any scan failure. Standing owner approval authorizes publication of sanitized milestone reports, status updates and eligible images embedded in those reports. Include each eligible report image. Apply this approval only when the exact outgoing diff has been inspected and the privacy validation passes. Publish using fast-forward pushes and verify the public URL anonymously.

## Session reporting

At the end of every Dynasty work session, refresh the public report and relevant status files with verified changes, tests, blockers and decisions, including partial or failed work. If the session produced no substantive project change, confirm the existing report is current. Honor any exact-snapshot approval specifically required for that session.

## Character-quality visual evidence

Every character-quality milestone needs matched before-and-after evidence for portrait, body and facial dialogue. Record candidate versions, defects, improvements, regressions and missing evidence. Publish sanitized cropped previews under the milestone images directory. The permitted formats are metadata-free low-resolution PNG comparison panels embedded in their own milestone report. Inspect the exact previews and binary-inclusive outgoing diff, and record image hashes against the reviewed tree before publication. Keep original references, full-resolution renders, editable assets and synchronized videos private. Publication approval and visual gate approval are separate decisions.
